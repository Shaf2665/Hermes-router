# Start here

Hermes Router connects your app to one or more AI providers. Your app sends a
message to Hermes; Hermes chooses a model and tries another eligible model if the
first one fails. Use a cloud provider, a model on your own computer, or both.

**Hermes is free software. AI providers may charge for their models.** You bring
your own provider account/API key or local model. Hermes does not include an AI
subscription or download models for you.

## 1. Choose where Hermes will run

Follow **one** installation path. You do not need every tool in the table.

| Your situation | What you need | Follow this guide |
| --- | --- | --- |
| Windows PC, without Docker | Python 3.10 or newer | [Windows setup](setup.md#windows-without-docker) |
| Mac or Linux computer, without Docker | Python 3.10 or newer | [Mac/Linux setup](setup.md#mac-or-linux-without-docker) |
| Docker is already installed | Docker Desktop or Docker Engine | [Docker setup](setup.md#docker-on-your-computer) |
| Linux server or VPS | SSH access; Docker or Python | [Server setup](deployment.md) |
| Windows Server | Python and access to the server | [Windows Server setup](deployment.md#windows-server) |

Your computer must stay on while it runs Hermes. A server can keep Hermes available
while your computer is off. The [Hermes website](https://hermes-router.vercel.app)
is documentation; your dashboard opens at the address of the router you start.

## 2. Know which key goes where

An API key is a secret password used by software. Hermes uses three different kinds:

| Key | Where it comes from | Where you use it |
| --- | --- | --- |
| Provider API key | Your AI provider's website | Hermes dashboard → **Providers** |
| Administrator key | Generated by Hermes on its first start | Dashboard sign-in; optional extension owner controls |
| Application key | Dashboard → **Connect** | VS Code or another app that sends AI requests |

Keep these separate. You do not need to invent a password or put a provider key in
VS Code. The setup guide shows how to find the generated administrator key.

## 3. Finish setup in your browser

After starting Hermes:

1. Open your router's dashboard. On the same computer, use `http://localhost:8319`.
2. Sign in with its **administrator key**.
3. Open **Providers**, choose your provider and paste its provider key. For a provider
   with free models, keep **Model selection** on *Automatically add free chat models*.
   For a paid account (such as OpenAI or Anthropic), choose models manually.
4. Click **Save provider**. Automatic selection applies immediately. A new key with
   manually chosen models needs a restart; the [setup guide](setup.md#1-add-your-ai-provider)
   shows how for your installation.
5. Open **Connect**, create an **application key**, and copy it when shown.
6. Click **Send test request**. A reply confirms that your provider and model work.

The [setup guide](setup.md#connect-a-provider-and-test-it) explains these steps,
including local models. Adding a provider can trigger small background checks;
these and the test message use the provider's quota.

## 4. Connect your app

For **VS Code and Copilot Chat**, follow the [extension tutorial](vscode-extension.md).
For an **OpenAI-compatible app** on the same computer, use:

| App field | Value |
| --- | --- |
| API base URL | `http://localhost:8319/v1` |
| API key | The application key you just created |
| Model | `hermes-router` |

For a server, use your SSH tunnel or HTTPS address instead of assuming that
`localhost` points to the server. [Server setup](deployment.md) explains both options.
Python and Anthropic examples are in [Use the API](usage.md).

## If something does not work

Start with the [setup troubleshooting table](setup.md#troubleshooting).
A working dashboard or `/health` page means Hermes is running; the test message
checks that an AI model can actually reply.

Once your first message works, add more [providers](providers.md), change
[settings](configuration.md), or inspect [activity and usage](monitoring.md).
